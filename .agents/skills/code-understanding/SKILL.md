# 代码理解统一入口

先回答用户想理解的问题，再按证据需要选择后端。保持用户指定的项目、范围、深度和交付形式。

本项目未安装 research 系列技能，默认独立执行代码理解。只有调用方已提供 research 执行上下文且安装了对应技能时，才读取兄弟目录 `research/references/code-understanding.md`，使用当前任务的问题、版本和产物位置；整个调用只返回一次证据，不重新建立调研计划。

## 选择工作流

| 问题类型 | 主路径 | 何时补充其他后端 |
|---|---|---|
| 单个函数、文件或小模块 | 直接读源码，结合已有索引定位上下游 | 跨文件上下文不清楚时查 GitNexus；已有 `.ua` 图谱时可用 understand-explain |
| 某项功能如何实现、请求如何流转 | 定位入口和符号，沿调用链阅读关键源码 | 跨文件调用难以定位时用 GitNexus，有项目背景需求时复用现有导览 |
| 限定模块的跨仓分析或文章技术取证 | 逐仓预检，沿限定模块的入口与直接调用链核对实现 | 现有索引匹配 checkout 和范围时优先复用，调用关系难以定位时再按需建立索引 |
| 陌生项目整体理解、入职导览、阅读路线 | Understand Anything 按项目或子系统建立架构和业务视图 | 用 GitNexus 核对关键入口与调用链 |
| 设计文档、协议、论文与代码的对应关系 | Graphify 关联选定材料与实现 | 用 GitNexus 定位关键符号，再回查源码 |
| 明确要求全面理解源码及设计材料 | 分模块组合三者，复用已有结果 | 按当前问题推进，避免一次重复读取整个项目 |

按问题选择后端，优先遵循用户明确指定的工具。直接阅读足以回答时，先定位文件和符号，再按行区间读取。限定子模块时，只向目录外追踪直接相关的装配点、适配器、消费者和验证入口。跨模块关系仍不清楚时，再按范围选择图谱。

## 绑定项目与准备后端

技能安装目录和待分析代码目录相互独立；目标可以位于任意其他仓库、磁盘或普通源码目录，无需复制进技能仓库，也不要求目标项目安装这些技能。

先绑定用户指定的仓库或路径，复用对话中已明确的项目。“当前项目”在工作区能唯一确定时可直接绑定。远程仓库先核对版本并取得可阅读的源码，再向本地 preflight 传入实际目录。

未指定源码时不自行搜索仓库。源码会影响结论时，可引导用户提供链接或本地路径，并允许跳过。跳过后继续分析已有材料，标明缺少源码依据的结论。已指定的单仓和多仓任务按[仓库绑定与记录](references/repository-record.md)逐仓预检并汇总。只有需要比较用户提供的候选、核对独立的版本映射或调用方明确要求结构化选择记录时，才运行选择检查。

所有脚本路径都相对本技能目录解析；相对目标路径按调用时的工作目录解析。进入后端工作目录前，把需要显式传递的项目和输出路径转换为绝对路径。

```sh
node <skill-dir>/scripts/preflight.mjs --target <project-or-file> --backend source
node <skill-dir>/scripts/preflight.mjs --target <project> --backend gitnexus --prepare
```

普通检查只读取项目、Git 状态和已有结果位置。`--prepare` 只准备指定后端的运行依赖；它不创建项目索引，也不生成报告。`--backend all` 仅在确实需要检查或准备三者时使用。详细参数与初始化条件见 [运行说明](references/runtime.md)。

记录目标真实路径、Git 提交、分支、工作树以及未提交变更摘要。后续后端的工作目录、源码、Git 状态和索引均绑定目标项目，运行依赖仍从技能目录定位。后续后端使用同一份 checkout 和分析范围；未提交内容也可能使索引过期。脚本的 `present` 只说明文件存在，不能当作索引新鲜或覆盖完整的证据。

按需读取选定后端技能和它的本地运行说明：

- GitNexus：[代码探索](../gitnexus-exploring/SKILL.md)、[本地入口](../gitnexus-cli/LOCAL_INSTALL.md)。需要建索引或 embeddings 时再读 [CLI 技能](../gitnexus-cli/SKILL.md)。通过已有可迁移入口运行，按 registry 中的真实路径匹配目标，再显式传递对应 repo。即使 registry 只有一个项目，也须先确认它就是目标；不能查询到技能仓库或其他项目。检查索引新鲜度，只为语义检索需要生成 embeddings。
- Understand Anything：[总体分析](../understand/SKILL.md)。依任务读取 [模块解释](../understand-explain/SKILL.md)、[问答](../understand-chat/SKILL.md)、[导览](../understand-onboard/SKILL.md) 或 [业务视图](../understand-domain/SKILL.md)。解释等子技能需要图谱；图谱不存在时，根据任务规模决定建立它还是直接读源码。保持当前 worktree，避免上游默认重定向到主 checkout。
- Graphify：[图谱技能](../graphify/SKILL.md)。优先查询已有图谱；需要构建时限制到相关源码和材料。使用本入口准备的固定版本运行环境，见 [运行说明](references/runtime.md)，不要因读取上游安装示例而升级全局工具。

现有索引须由对应后端检查版本和覆盖范围，再决定是否更新。依赖准备失败时，说明缺失能力；能够直接阅读源码的部分继续执行，不把失败查询当作“实现不存在”。

调用后端时保持已绑定的目标、版本、范围和输出目录；本地运行说明优先于上游示例的默认 cwd、全量扫描或输出位置。原生图谱／报告属于工具产物，按当前任务管理，不另开一套 research 流程。

## 汇集证据并讲解

用文件路径、符号和行号串联已使用的证据，各后端产物保留原格式。重要结论回查当前源码，分别标记源码事实、静态关系、模型推断和运行验证。后端结论不一致时，核对 checkout、未提交变化和索引覆盖，再阅读争议源码。动态分派、反射等静态分析缺口保留为不确定性。

由 research-deep 调用时，按原问题／field_id 返回结论、源码位置、适用版本、推断／运行条件与缺口，由 research-deep 统一写入当前 light/full 记录并判断完成度。由 wechat-article 调用时，按[技术文章交接](references/explanation.md#给技术文章交接)返回逐主张的证据和可公开表述范围。

按照用户问题组织回答。典型功能讲解包含入口、主要步骤、数据流、关键分支和源码位置；项目导览包含模块职责、业务路径和推荐阅读顺序。按需读取 [讲解与证据约定](references/explanation.md)。

独立调用时默认在聊天中回答。用户要求文档时保存到指定位置或目标项目已有的文档位置。完整开源项目调研可交给已安装的 `research-open-source`，传递用户指定的仓库和跳过源码的选择，并沿用同一源码范围约束。该技能缺失时，继续处理有来源支撑的分析。绘图或交互页面按需使用对应技能。
