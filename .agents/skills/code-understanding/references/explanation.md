# 讲解与证据约定

按问题选择表达方式，无需为每次回答套用完整模板。

## 函数或文件

先说明它在业务和模块中的职责，再按输入、处理、输出解释。阅读实际实现，必要时展开调用者、被调用者、共享状态和错误路径。复杂语言特性只解释与本段实现相关的部分。

## 功能与调用链

从真实入口沿调用方向解释关键步骤，注明异步边界、状态变更、事务、外部服务和主要失败路径。图谱提供定位线索，最终引用来自当前源码。列出关键文件和符号，避免逐行复述所有实现。

按宿主从接口及实现查到注册或绑定、实际触发点、配置和运行条件，再核对结果及失败处理。按证据区分已有接口或实现、静态可见的产品接入、依赖条件的接入，以及实际运行验证。调用被注释、依赖缺失或没有找到生产入口时，写明对应的接入缺口。

跨仓复用逐项记录提供方、宿主使用的组件、实际调用边界和生效责任。共享事件模型和安装目录时，仍分别核对各宿主的发布、重载、失败恢复和清理路径。例如，一个宿主在新批次成功后撤销旧 Handler，另一个宿主先撤旧再发布，须分别描述两条重载路径。

## 整仓阅读与导览

说明项目要解决的问题和运行入口，划分主要模块，选择一条代表性业务流程串联它们。给出有理由的阅读顺序：先读什么、能理解什么、再跳到哪里。尊重用户指定的子系统范围。

## 文档与实现对应

把文档中的术语、约束和流程，关联到源码符号及配置。注明文档版本和实现版本。文档宣称的行为、静态代码支持的行为、实际执行结果分别陈述；无法定位的对应关系保留为缺口。

## 证据

- 绑定项目真实路径、Git 提交及本次未提交变更摘要；非 Git 源码可记录内容快照哈希，无法核实的发布版本仍标为未知。
- 对关键判断记录文件、符号和紧邻的行号。落盘时保留可点击的本地引用，以及可重定位的仓库来源、完整 commit、仓内路径和符号或行号。若结论依赖未提交内容，另记相应变更依据。
- 事实以当前源码为依据；图谱的推断边、业务语义总结和作者设计意图分别标记。
- 运行验证只引用实际执行过的命令和观察结果，不能把“存在测试文件”写成“测试通过”。
- 静态索引查不到调用者，可能来自分析范围、过期索引、动态加载或解析器限制，不足以证明没有调用者。

### 给技术文章交接

对每个待写主张给出目标版本、相关入口或符号、适用条件、核验层次和可公开表述的范围。核验层次区分接口存在、目标产品接入、已运行验证和规划。讲扩展机制时，可按加载和生效链路、事件触发时机、事件处理函数可调用的能力组织证据。用户仅要求核查参考实现时只交付该实现的事实，产品接入状态留待后续核对。文章技能负责读者表述和素材归档。

## 成本与续查

先搜索文件名和符号，再分批读取命中的行区间。限定子模块时，以模块内证据为主，只沿直接调用关系核对目录外的宿主入口、适配器、消费者或测试。源码足以核查时直接阅读。调用链难以定位时，按需复用或建立与当前 checkout 和范围匹配的索引。续查只更新受变化影响的证据。
