# 正文与媒体核对

当 HTTP 响应缺少动态正文、转载页面的图片地址失效、解析结果吞掉正文，或文章包含内嵌视频时使用。

## 从已有正文接续归档

- HTTP 正文为空或仅有页面框架时，先确认现有浏览器标签页是否已经显示原文。读取实际承载正文的容器，并保存原标题、来源 URL、当前 URL、正文 HTML、可见文字和图片顺序。站点选择器以本次页面实际结构为准。例如极客公园可核对 `#article-body`，腾讯云开发者社区可核对 `.mod-content__markdown`。
- 保留正文中的标题、段落、链接、图注和作者署名。站点生成的概览、导航、评论和推荐应在确认边界后排除。保存原始快照，清理后的 HTML 另存一份。已绑定写作主题时放在该主题的 `.tmp/`。
- 微信使用[现有快照入口](wechat-verified-browser.md#4-用快照入口继续归档)。其他站点需要本次任务的离线转换适配时，把已捕获的 HTML 作为归档管线的正文输入，复用标题命名、图片下载和归档检查，并记录实际获取方式。适配器应使用该任务的文件路径与来源参数，留在任务临时目录。
- 转存前后核对正文首尾、可见文字、链接目标和媒体位置。需要记录文字指纹时，注明规范化范围，仅忽略确认属于排版的差异。图片顺序按正文每次出现记录，包括重复项。

## 处理转载图片和解析异常

- 对比浏览器实际显示的资源和 DOM 属性。正常懒加载图片可用 `data-src` 等字段。转载页面若已有可验证的本站图片 `src`，且旧的转载源字段返回防盗链占位图，则采用实际显示的资源，并记录页面 URL 与采用地址的对应关系。只有能核实为同一资源时才复用已有图片。
- 图片文件格式和下载状态检查通过后，仍需确认内容是原图。遇到多张不同图片下载成同一占位图时，回查浏览器显示的资源。无法确认正确地址时，保留可追溯的原图引用并记录缺口。
- 畸形 HTML 可能使解析器把后续文字误挂在 `img` 等空元素下。先比较 DOM 与解析结果的正文文字和段落，再用浏览器规范化后的 DOM 或已有的其他解析器复核。确认确实没有资源地址的空图片节点可移除。清理后重新核对正文文字和图片顺序。
- 修复已有归档时先准备候选并核对来源、正文、图片映射和相对路径。候选通过检查后再替换对应文件，按实际变化更新元数据与散列。

## 保留视频原位置

- 微信正文中发现 `span.video_iframe` 时，核对元素提供的远程地址，例如 `data-src`。可验证的地址可在原位置保留为正文链接。页面显示时长时一并记录，缺失时留空。
- 按正文出现顺序记录视频地址、时长和获取状态。保留远程链接时状态记为 `remote`。另存视频按用户范围和实际可访问性处理。
- 视频区域转换后核对其原位置、相邻段落和图片出现顺序。使用 `--validate-only` 检查归档文件和图片，再以正文快照复核文字和视频链接。
