# 大纲生成与确认

适用于首次大纲、已有大纲调整，以及正文改动导致的大纲同步。先满足入口的信息与资料条件，再执行本流程；本文件统一规定大纲内容、确认效力及变更边界，归档操作和编号统一见[版本规范](versioning.md)。

## 流程状态

| 状态 | 可以进行的操作 | 进入下一步的条件 |
| --- | --- | --- |
| 标题待选 | 核对事实与结构，展示文章、章节及子章节的标题候选 | 用户明确选定或提供每项标题 |
| 内容核对 | 以选定的标题组织工作稿，逐组讨论导语、各节概述和媒体 | 各组已核对，可以汇总供最终确认 |
| 完整稿待确认 | 展示汇总后的具体完整大纲，可保存无版本号的工作稿 | 用户明确最终确认这版完整稿 |
| 已确认、待归档 | 保持获确认内容不变，准备文件和确认记录 | 落盘任务先归档大纲及元数据；仅聊天任务直接以确认稿作为基线 |
| 可展开正文 | 落盘任务使用已归档大纲，仅聊天任务使用已确认稿；按正文流程从导语开始逐章写作 | 每章核对资料、处理配图并获用户确认后再写下一章；全部完成后汇总检查、保存正文版本 |

只确认大纲不代表请求新增正文；已有成稿请求的，确认后可直接开始导语单元，但仍须按[正文流程](chapter-workflow.md)逐章取得确认，不能用大纲批准替代章节正文批准。大纲确认针对写作范围、结构和安排，不替代事实与代码核查，也不代表正文已获发布批准。改变已确认内容时先形成工作稿，再按[版本规则](versioning.md#统一命名)保存确认后的修订。

## 大纲应包含的内容

| 内容 | 要求 |
| --- | --- |
| 文章标题 | 首轮给出 2–3 个有不同侧重点的候选并标明推荐，完整稿保留用户选定的唯一标题 |
| 章节与子章节标题 | 标明拟采用的层级和顺序，每章和每个实际子章节均给出 2–3 个候选并标明推荐。章内分点按内容组织，不自动升级为标题 |
| 正文导语 | 说明用什么任务阻碍引入、怎样讲清本次能力及读者价值。默认写成简明概述，正文阶段再展开 |
| 章节导语 | 主章有子章节时，核对该章概述时请用户选择是否添加章导语。选择添加后，先单独核对章导语概述，再确认子章节。 |
| 章节及子章节概述 | 默认一小段，说明回答什么问题、从哪里切入、按什么顺序展开。必要的证据定位放内部核对依据；尚未需要确定的正文细节留到写作阶段 |
| 图片与视频占位 | 一般按需选用；场景要求逐项演示时，每项必须保留对应的视频或图片，形式可选但演示不可省。每项有编号和明确标题，并说明具体位置、内容、论证用途及素材状态，后续文件名沿用同一编号和标题 |
| 内部核对依据 | 集中保留来源、代码版本、事实边界与获准差异，不混入导语或未来正文 |

概述用连贯的短段说明“准备怎样写、为什么这样推进”，不必机械拆成固定条目。例如，写机制小节时可说明“先从前章任务的一个失败点提出问题，再沿输入到输出解释处理过程，用已核实实现支撑原因，最后回扣案例结果并引出验证”。具体内容随主题填写，不能只复述标题，也不提前扩写为完整正文。

按需在概述中安排各章详略、主要信息增量和转场目标，提前发现重复或失衡；用户给出总篇幅时据此分配，不要求固定字数，也不新增独立篇幅确认。内部依据引用实际图片文件时保留有效相对路径，素材保留集合会同时检查已确认大纲。

需要媒体时使用统一占位格式，如 `【图片占位 图1：任务流程图｜待绘制。说明从输入到交付的过程。】`、`【视频占位 视频1：任务结果核对｜待提供。打开结果页并核对任务状态。】`。占位紧跟它支持的内容。内部登记保留稳定 ID，读者编号和后续文件命名按[媒体规范](media-workflow.md)。采用后保持编号稳定，确认关键点、case 与媒体的对应关系。完整大纲按正常流程最终确认。

## 使用场景模板

生成大纲前读取所选场景的模板；当前 openJiuwen 使用[场景模板](../assets/outlines/openjiuwen-outline.md)，确认状态见[场景约定](scenarios/openjiuwen.md#大纲模板)。以推荐骨架起步，按目的和证据取舍；不同章节可采用不同写法，章内可组合案例、机制、演示与对照，不固定子节数量和媒体位置。只有结构选择确实影响主线时才给少量方案，不单设结构审批。

按需读取[样文填写示例](samples/openjiuwen/writing-guide.md#模板中的运用)，将所借写法转成当前材料支持的概述，内部简记实际位置、方法与落点。样文的章序、主张和媒体数量不自动带入。

openJiuwen 场景拟定关键差异／竞争力时，可按[特性比较与建议方法](scenarios/openjiuwen.md#形成关键差异与竞争力建议)，以本方代码、设计及相关资料对照竞品宣发材料提出候选，再落到本篇 case 和演示计划。候选选择并入现有讨论，确认与归档节点不变；不要求本方宣发软文，也不要求每篇必须有竞品资料或比较结论。

模板待确认时先展示，记录真实回复及批准范围；确认一次即可用于具体大纲。模板骨架、必填内容或媒体要求改变时，展示修改供确认；仅补样文、修复链接或改进不改变要求的示例，不重确认模板。模板更新不追改已有大纲；模板确认也不批准具体文章。

最终待确认稿要选定实际标题、章节、写法和媒体计划，移除模板参考区、占位变量、未选项及组织提示，校准章节序号和回指；已确认的媒体编号及稳定单元 ID 不随章序重排。概述具体说明怎样写，不能仍让正文阶段另选论证路线；样文人物、任务和数据不得误带入。未配置模板的场景按本文件内容清单组织。

待制作演示写清设计、观察目标和计划状态；大纲确认只批准安排，不验证结果。已有证据才能写成事实，实际演示不符且影响主张时修订大纲。候选标题、讨论轮次与状态放在稿件外，归档仅保留选定内容及内部依据。

## 与用户协作

1. **逐项确认标题。** 根据素材拟定主线和章节层级。先确认文章标题，再按顺序确认主章节标题，最后依次确认子章节标题。每轮只提供一个可确认的标题项及其候选，说明侧重点并标明推荐。左侧目录展示所有标题、层级和状态。用户可选择、自拟或提出重拟意见，也可批量反馈多个章或子章节的修改方向。收到「基于 B」「后半句微调」时读取该轮 B 的全文，保存基准稿次、候选字母、锁定原文和允许改动的范围，只在该范围内给候选。批量反馈可以调整一组候选的写法，各标题仍分别确认。沿用已确认且未受影响的标题。展示前执行[事实核查与润色](facts-and-style.md)。
2. **逐项核对内容。** 各级标题选定后，每次展示一项概述和对应媒体。含子章节的主章须先选择是否添加章导语。选择添加后，在主章和子章之间加入单独的章导语概述，确认后再逐项确认子章。写正文时按选定安排处理。确认和修改意见只作用于当前项。保留已确认概述，原页默认打开首个待核对项。收到修改意见后重新展示修订内容，全部确认后再汇总。标题改动回到标题阶段，并重新核对受影响的内容。
3. **预览完整稿并最终确认。** 汇总已选标题和分组反馈，以讨论轮次标识展示具体完整稿及重要变化。按模板清理未选项、校准回指，先处理关键事实缺口，再请用户明确确认该完整稿。标题选择、分组确认、草稿保存和预选均属于过程状态。用户一次明确同意已展示的完整稿及其选择时，使用该次确认。遇到“把第二章改成 X 后就按此归档”一类附条件批准，可以准确应用指定变更并说明结果；涉及自主补充时，先展示修订稿再确认。
4. **交接归档。** 锁定实际获确认的内容与讨论稿标识，交给版本流程保存。确认后再有改动，按下方规则返回工作稿。元数据采用用户真正发到对话里的最终确认。

优先用 [HTML 确认向导](outline-review-ui.md)分步展示。每篇复用一个页面地址，更新其中的当前项。交付稳定的手动链接，按当前轮次校验 JSON 反馈，再应用选择或修改。用户指定纯文字或无法交付 HTML 时，按相同阶段用聊天推进。需要持久保存时将 `outline-working.md` 放在对应的 `article/vNNN/`，可随讨论更新。正式大纲单独保存为同目录的 `outline-vNNN.md`，正式版本记录以它为准。状态、讨论轮次及基线说明与大纲正文分开。

应用反馈前以轮次、阶段和条目 ID 确定目标。`sections` 阶段选中 C1 时，意见中提到「导语」可能指本节的开头；只有用户明确指定全文导语或确认了目标切换，才修改导语项。确实指向两个不同对象且会影响已确认文字时，先用对话核对目标。改稿后比较受影响项，其余项逐字保留。恢复上一版时读取实际快照，对照原确认；只有恢复到确切确认稿才恢复确认状态。完整稿可通过原反馈框修改标题、概述或结构，按涉及范围重开相应项。切换到聊天时记录当前轮次和待确认项，沿用原确认及同一份工作稿。

仅聊天交付时仍需完成大纲确认，随后按请求逐章写作和确认；不写文件、不分配版本。只请求标题候选、局部措辞建议或纯审稿时，不借此启动整篇大纲审批。

## 确认后的变更

| 情况 | 处理 |
| --- | --- |
| 改文章或各级标题、章节顺序、导语含义、主线、关键事实、边界，或改变概述确定的论证路线、比较对象、媒体用途或验证设计 | 修订大纲工作稿，确认受影响内容后按[版本规则](versioning.md#统一命名)保存，再同步对应正文 |
| 正文内润色、改错字、调整标点或细化不超出概述的解释 | 沿用原大纲。需要同步标题显示时仅改明确指定的标题。正文改动只涉及当前单元及其确认，仍处同轮时并入当前工作版 |
| 同一媒体的显示编号、标题、描述或文件名调整，或将占位落实为同用途素材 | 按[媒体规范](media-workflow.md#确认与归档边界)处理；仅在用户指定或维护有效引用时同步当前大纲相应字段，不触发重新确认整份大纲或自动增版 |
| 新读样文、更新索引／指南、复核或补充来源，但不改变大纲内容、既定论证逻辑和事实结论 | 不自动重建或确认大纲；继续沿用原基线。新增核查与来源记录放在工作上下文或本篇 `refs/sources.md`，不回填历史大纲；需要修改大纲内容时按相应变更处理 |
| 修改已获确认大纲本身的措辞、核对依据或其他文字，即使不改章节结构 | 先形成工作稿，确认变更后保存到当前大纲版本。需要新增版本时先取得用户确认 |
| 将获确认的聊天大纲排版、编码为待归档文件 | 不改变展示文字、层级和含义；文件名、换行与外部状态标记不属于大纲内容变更。已归档文件仍保持不变，不能借格式整理覆盖历史或重写文字 |

正文若必须使用超出原大纲的新事实或不同媒体计划，不以“细节展开”绕过确认；代码复核发现关键事实不成立时，同样先纠正大纲再请用户确认。用户明确要求省略某类媒体、只交付大纲或只做局部修改时，保持其范围。
