# 大纲生成与确认

适用于首次大纲、已有大纲调整，以及正文改动导致的大纲同步。先满足入口的信息与资料条件，再执行本流程；本文件统一规定大纲内容、确认效力及变更边界，归档操作和编号统一见[版本规范](versioning.md)。

## 流程状态

| 状态 | 可以进行的操作 | 进入下一步的条件 |
| --- | --- | --- |
| 工作稿／待最终确认 | 展示完整大纲、讨论标题和结构、核对资料；可保存无版本号的工作稿 | 用户明确最终确认所展示的具体完整稿 |
| 已确认、待归档 | 保持获确认内容不变，准备文件和确认记录 | 落盘任务先归档大纲及元数据；仅聊天任务直接以确认稿作为基线 |
| 可展开正文 | 落盘任务使用已归档大纲，仅聊天任务使用已确认稿；按正文流程从导语开始逐章写作 | 每章核对资料、处理配图并获用户确认后再写下一章；全部完成后汇总检查、保存正文版本 |

只确认大纲不代表请求新增正文；已有成稿请求的，确认后可直接开始导语单元，但仍须按[正文流程](chapter-workflow.md)逐章取得确认，不能用大纲批准替代章节正文批准。大纲确认针对写作范围、结构和安排，不替代事实与代码核查，也不代表正文已获发布批准。任何需改变获确认大纲内容的情况，回到工作稿状态，旧正式版本及其确认保持不变。

## 大纲应包含的内容

| 内容 | 要求 |
| --- | --- |
| 文章标题 | 工作阶段可有多个候选；归档时保留用户选定的唯一标题 |
| 章节与子章节标题 | 展示实际采用的层级和顺序；章内可用自然段、整体介绍加分点，或在确需分组时设置子章节，分点不自动升级为标题。实际标题可提供多个候选供选择 |
| 正文导语 | 给出接近成文的导语文字，交代任务问题、本次能力和阅读价值，不只写“此处写导语” |
| 章节导语 | 可选；需要转场或解释章节目的时给出简短草稿，不强制每章都有 |
| 章节及子章节概述 | 讲清本部分的写作思路与逻辑：回答什么问题、从哪里切入、按什么顺序或因果关系展开、用何种事实或证据支撑、得到什么判断，以及怎样衔接上下文；不能只列主题或知识点 |
| 图片与视频占位 | 一般按需选用；场景要求逐项演示时，每项必须保留对应的视频或图片，形式可选但演示不可省。每项有编号和明确标题，并说明具体位置、内容、论证用途及素材状态，后续文件名沿用同一编号和标题 |
| 内部核对依据 | 集中保留来源、代码版本、事实边界与获准差异，不混入导语或未来正文 |

概述用连贯的短段说明“准备怎样写、为什么这样推进”，不必机械拆成固定条目。例如，写机制小节时可说明“先从前章任务的一个失败点提出问题，再沿输入到输出解释处理过程，用已核实实现支撑原因，最后回扣案例结果并引出验证”。具体内容随主题填写，不能只复述标题，也不提前扩写为完整正文。

按需在概述中安排各章详略、主要信息增量和转场目标，提前发现重复或失衡；用户给出总篇幅时据此分配，不要求固定字数，也不新增独立篇幅确认。内部依据引用实际图片文件时保留有效相对路径，素材保留集合会同时检查已确认大纲。

需要媒体时使用清楚的占位文本，如 `【图片占位 IMG-01：任务流程图；待绘制；用途：说明输入到交付的过程】`、`【视频占位 VID-01：操作演示；待提供；用途：展示结果核对】`，冒号后的名称即该媒体标题，不用不存在的文件引用。编号、标题、后续文件命名及 PNG 要求统一见[媒体规范](media-workflow.md)。采用后保持编号稳定并同步标题、位置、用途；未采用的可选占位可移除，场景要求逐项演示的内容则必须检查关键点、case 和媒体的一一对应。完整大纲按正常流程最终确认。

## 使用场景模板

生成大纲前读取所选场景的模板；当前 openJiuwen 使用[场景模板](../assets/outlines/openjiuwen-outline.md)，确认状态见[场景约定](scenarios/openjiuwen.md#大纲模板)。以推荐骨架起步，按目的和证据取舍；不同章节可采用不同写法，章内可组合案例、机制、演示与对照，不固定子节数量和媒体位置。只有结构选择确实影响主线时才给少量方案，不单设结构审批。

按需读取[样文填写示例](samples/openjiuwen/writing-guide.md#模板中的运用)，将所借写法转成当前材料支持的概述，内部简记实际位置、方法与落点。样文的章序、主张和媒体数量不自动带入。

openJiuwen 场景拟定关键差异／竞争力时，可按[特性比较与建议方法](scenarios/openjiuwen.md#形成关键差异与竞争力建议)，以本方代码、设计及相关资料对照竞品宣发材料提出候选，再落到本篇 case 和演示计划。候选选择并入现有讨论，确认与归档节点不变；不要求本方宣发软文，也不要求每篇必须有竞品资料或比较结论。

模板待确认时先展示，记录真实回复及批准范围；确认一次即可用于具体大纲。模板骨架、必填内容或媒体要求改变时，展示修改供确认；仅补样文、修复链接或改进不改变要求的示例，不重确认模板。模板更新不追改已有大纲；模板确认也不批准具体文章。

最终待确认稿要选定实际标题、章节、写法和媒体计划，移除模板参考区、占位变量、未选项及组织提示，校准章节序号和回指；已确认的媒体编号及稳定单元 ID 不随章序重排。概述具体说明怎样写，不能仍让正文阶段另选论证路线；样文人物、任务和数据不得误带入。未配置模板的场景按本文件内容清单组织。

待制作演示写清设计、观察目标和计划状态；大纲确认只批准安排，不验证结果。已有证据才能写成事实，实际演示不符且影响主张时修订大纲。候选标题、讨论轮次与状态放在稿件外，归档仅保留选定内容及内部依据。

## 与用户协作

1. **给出可讨论的初稿**：生成完整大纲工作稿，简短说明推荐主线。对文章标题、重要章节或子章节标题，可提供少量有差别的候选，编号如 `T1/T2`、`C1-A/C1-B`，说明各自侧重点并给出推荐；不强制每个标题都列候选。展示前执行[事实核查与润色](facts-and-style.md)。
2. **收集选择与调整**：让用户选择标题、调整章节及媒体安排，允许自由修改，也可分轮讨论。已确认且未变化的部分沿用，不重复追问。等待用户时可以核对事实和整理素材，不提前完成正文或归档大纲。
3. **汇总最终待确认稿**：合并选择和反馈，用讨论稿标识展示完整定稿及重要变化，例如“第 3 轮完整稿”；这不是正式版本号。按上方模板规则清理未选项、确认实际写作逻辑并校准回指。关键事实缺口先核实、删去或收窄；其余问题只保留在内部依据中，不作为已支持的核心论据。
4. **取得最终确认**：明确请用户确认所展示的具体完整稿。用户在确认请求后明确表示“确认”“就按这个大纲继续”等，且上下文唯一指向该稿时可视为最终确认；只选择标题、只要求继续讨论、未回复、超时或工具预选均不算。用户一次明确确认全部选择并同意完整稿时不再重复询问；“把第二章改成 X 后就按此归档”这类明确的附条件批准，可在准确应用该项变更并说明结果后使用；若还需自主补充或解释其内容则先展示修订稿再确认。
5. **交接归档**：锁定实际获确认的内容与讨论稿标识，交给版本流程保存。确认后不再改动稿件及其内部依据；需改时按下方规则返回工作稿。元数据的确认记录来自本次真实回复，不用模板或旧稿确认代替。

工作稿默认在聊天中展示；需要持久保存时用 `outline/outline-working.md`，可以覆盖修订，不使用 `vNNN`，不进入正式版本记录。状态、讨论轮次及基于哪个正式版本等说明与大纲正文分开保存或展示。归档后保留的工作稿只作为副本，引用时优先正式版本；下次调整从明确基线开始，不让遗留工作稿覆盖用户指定的版本。

仅聊天交付时仍需完成大纲确认，随后按请求逐章写作和确认；不写文件、不分配版本。只请求标题候选、局部措辞建议或纯审稿时，不借此启动整篇大纲审批。

## 确认后的变更

| 情况 | 处理 |
| --- | --- |
| 改文章或各级标题、章节顺序、导语含义、主线、关键事实、边界，或改变概述确定的论证路线、比较对象与演示验证设计、媒体标题、用途或位置 | 修订大纲工作稿，完成最终确认后归档新大纲，再写对应正文；即使文章标题未变也需同步实际写作逻辑 |
| 仅在正文里润色措辞、改错字、细化自然段、补充不超出概述的解释或案例 | 复核不改变事实和大纲承诺后沿用原大纲；修改已确认章节时仍需确认该章新稿，需要落盘则在完成确认后新增正文版本 |
| 将已规划的媒体占位替换为符合原编号、标题、用途和位置的真实图片、视频或链接 | 不因素材到位重确认大纲；按[媒体确认边界](media-workflow.md#确认与归档边界)核对实际素材，不能将占位批准视为实物批准。正文已归档时通过新正文版本落实，不覆盖历史文件 |
| 新读样文、更新索引／指南、复核或补充来源，但不改变大纲内容、既定论证逻辑和事实结论 | 不自动重建或确认大纲；继续沿用原基线。新增核查与来源记录放在工作上下文或本篇 `refs/sources.md`，不回填历史大纲；需要修改大纲内容时按相应变更处理 |
| 修改已获确认大纲本身的措辞、核对依据或其他文字，即使不改章节结构 | 先形成工作稿，再确认、归档新大纲；原确认不覆盖新内容 |
| 将获确认的聊天大纲排版、编码为待归档文件 | 不改变展示文字、层级和含义；文件名、换行与外部状态标记不属于大纲内容变更。已归档文件仍保持不变，不能借格式整理覆盖历史或重写文字 |

正文若必须使用超出原大纲的新事实或不同媒体计划，不以“细节展开”绕过确认；代码复核发现关键事实不成立时，同样先纠正大纲再请用户确认。用户明确要求省略某类媒体、只交付大纲或只做局部修改时，保持其范围。
