# 从 openJiuwen 样文到本篇写作

本文件把历史样文中的具体内容转成可选写法，供选题、大纲、正文和审稿时使用。按需要查看对应条目和原文，不必逐篇阅读。完整资料清单见[样文索引](index.md)。

按需跳转：[引用性质](#先判断引用性质)、[流程](#流程中的用法)、[原文定位](#可定位的内容与写法)、[组织取舍](#组织方式的取舍)、[约束](#从样文提炼的约束)、[模板填写](#模板中的运用)。

样文说明“曾经怎样写”，不代表其中主张已经核实。本文维护选文、解读和改编方法；资料门槛、事实／代码核查及 humanizer 以[技能入口](../../../SKILL.md)为准，大纲确认与变更以[大纲流程](../../outline-workflow.md)为准，正文推进以[逐章流程](../../chapter-workflow.md)为准，基线、文件、版本和来源追溯以[版本规范](../../versioning.md)为准。下文案例均是历史原文的转述；借鉴方法时，用本次材料替换人物、任务、操作、数据和入口。

## 先判断引用性质

| 用途 | 可以取用什么 | 使用前要完成什么 |
| --- | --- | --- |
| 写法借鉴 | 切入问题、任务推进、章节分工、解释顺序、演示观察点 | 阅读相应段落，判断它是否适合本篇目的与证据；用自己的表达重组，不把样文中的任务、术语或结论一并移植 |
| 事实引用 | 历史发布、机制、使用条件、实验及其结果 | 明确目标时间与版本，按入口核查；涉及代码时回到本篇目标实现。相关历史样文本身可作为资料，不必另找一份资料凑数量；仅借鉴文风则不满足资料门槛 |
| 媒体复用 | 原图及其所表达的界面、流程或结果 | 实际查看图片，确认内容、版本、标注和相邻结论适用；保留原归档，在本篇制作编号、标题一致的 PNG 副本并记录来源。视频文字说明只能参考脚本，不能代替视频文件或观看记录 |

同一篇样文可以承担多种用途，但逐项判断；读过原文、保存过来源元数据，不等于核实了其中全部事实。直接引用原句时标明出处，改编段落要重组表达，避免只替换产品名和少量词语。

## 流程中的用法

| 写作节点 | 如何使用样文 | 本次应落实的结果 |
| --- | --- | --- |
| 资料整理／核对 | 围绕本篇问题选相关段落；历史事实与目标版本核对，纯写法不混入事实清单 | 可用主张、条件和来源，不为复刻样文补造数据 |
| 大纲工作稿 | 按下表和模板示例选择切入、章节职责及论证方式，换成本篇任务与证据 | 内部简记“样文位置—借鉴方法—本篇落点”，不另写逐篇报告 |
| 正文展开 | 仅用相关段落帮助组织本章的动作、原因与观察点 | 沿用章节流程，不用读过样文代替本章取证 |
| 润色／检查 | 检查是否误带旧数据、入口、第一方口吻或人物 | 清除样文残留，保持本篇事实与声音 |

这些动作用于现有流程，不新增选文审批或版本节点。最终稿清除模板参考区及提示；确认、归档与后续变化按[大纲变更规则](../../outline-workflow.md#确认后的变更)，来源及路径按[追溯规范](../../versioning.md#参考材料与历史追溯)执行。

## 可定位的内容与写法

| 样文与定位 | 原文如何推进 | 本篇可以借鉴什么 |
| --- | --- | --- |
| [永续会话][persist]：导语及“一、五个人共用一个 Agent，它能分清谁说了算吗？” | 从长期工作中的人员、职责和约定变化提出问题，以活动改期、联系方式分享等冲突展开，截图和视频说明指向具体决定 | 导语提出可观察的问题；case 挑选能检验主张的转折，不按全部聊天记录流水叙述。视频说明先告诉读者看什么 |
| [Computer Use][cua]：“01 日常任务交给 Agent，从 WorkSwarm 开始”及“02 面向长程任务，让多步操作连续推进” | 用读邮件、预定会议、回复结果串联一项任务，再解释每步操作与界面反馈的关系，区分 Agent 判断和组件执行 | 能力章写清输入到交付；技术章解释反馈怎样支撑下一步，两章可引用同一任务而回答不同问题 |
| [个人知识空间][knowledge]：整体四层流程、“按需使用”及“效果对比” | 先说明来源、采集、处理、使用的关系，再写用户入口与逐步读取；效果说明保留资料预处理和任务使用的区别 | 架构／流程总览后按需要分点解释；使用路径有起点和结果；成本收益注明发生阶段，不把预处理当作免费 |
| [双维度 RSI][rsi]：“工程闭环”及“Harness 优化：四步把失败案例变成即装即用的新能力” | 先分清任务、优化、执行和基础框架职责，再从数据准备写到创建实验、观察迭代和安装产物 | 技术设计用职责与证据流解释能力；操作章围绕首次获得可用产物，不把层次名称当操作步骤。原文的四步数量不必照搬 |
| [WorkSwarm 产品升级][workswarm]：“二、实战”及“三、差异化体验” | 按办公、编程、生活娱乐分组呈现案例，再归纳协作、经验复用等价值 | 多场景选择互补的任务，归纳价值时回指具体 case；原文中缺少逐项演示的卖点，按本篇现行规则补齐证据或删去，不照搬其绝对比较措辞 |
| [Agent-Memory][memory]：“二、OmniMem-Lens”及“四、两个例子” | 从事件边界、记忆层级和离线／在线分工解释设计，再用事件跨窗口、静止画面中话题变化等例子说明差异 | 用互补失败条件解释不同设计为何必要；图示适合说明边界和关系，不能据此宣称普遍成功率。技术机制及案例真实性仍需本次资料核实 |
| [智能体资产平台][assets]：“Agent 资源如何形成生态闭环”“五类资源详解”及“从单专家到专家团” | 先交代资源生命周期，再区分方法、外部接入、能力打包、角色和协作，最后用单专家与专家团任务串起关系 | 生态题材先讲资源怎样配合，再按职责解释；保留模板／配置与运行实例的区别，避免五类资源反复重复同一套介绍 |
| [Hyper-Agent][hyper]：“超级智能体蜂群架构”、3.1、3.2 及 4.2 | 架构图交代身份、会话和调度关系；跨渠道与跨设备分别演示；咖啡店任务从单专家调研接续到专家团规划、多团队筹备 | 架构总览与具体设计可混合分点、子节；一条任务可贯穿多个演示项，但各项分别说明任务阶段、关键差异和自己的视频或图片 |

## 组织方式的取舍

推荐骨架仍以[场景大纲模板](../../../assets/outlines/openjiuwen-outline.md)为起点。先确定各章回答的问题，再选章内写法；可以组合，但不能把多篇样文的目录直接拼接。

| 组织方式与样文 | 什么时候选 | 怎样取舍或组合 |
| --- | --- | --- |
| 一项任务贯穿：Computer Use | 一条任务已能呈现输入、推进和交付 | 能力章呈现任务，设计章解释原因，使用章给起点，竞争力章选可检验差异的环节；没有必要不反复重述全过程 |
| 整体说明加要点：个人知识空间、RSI、Hyper-Agent | 先理解职责或数据／状态流，才能看懂设计价值 | 先总览再解释关键设计，短内容用段落或分点；独立问题才设子节。多个角度可组合，图仍可选 |
| 互补 case 并列：永续会话、Agent-Memory、WorkSwarm 产品升级 | 不同 case 分别支撑不同关键点，单个任务无法覆盖 | 每项回答不同问题；若只更换人物或应用而论证相同，则合并或择一。每项关键点分别有具体 case 和独立编号的视频或图片 |
| 同一任务逐步扩展：Hyper-Agent 咖啡店任务 | 后一阶段真实依赖前一阶段成果，且新增协作方式值得解释 | 逐次增加任务约束或参与角色，说明新增价值；从连续任务中分别截取对应片段或图片并编号，避免用一段泛化演示替代所有关键点 |
| 资源职责与流转：智能体资产平台 | 多类资源容易混淆，文章重点是组合与复用 | 先交代共同任务及资源关系，再解释有关的职责和流转；不为凑齐分类增加无关资源，不默认扩展到发布、共建 |

复用同一案例时检查章节分工：能力章回答“任务发生什么变化”，设计章回答“哪些机制使其成立”，使用章回答“读者怎样首次用起来”，竞争力章回答“在哪个具体条件下体现哪项价值、证据是什么”。本篇不需要的章节可裁剪；不能用名称相近的章节反复介绍同一卖点。

## 从样文提炼的约束

通用事实、代码对齐及润色要求见[技能入口](../../../SKILL.md)。以下用样文中的具体情况帮助执行这些要求：

| 样文中的情况 | 本次写作怎样处理 |
| --- | --- |
| 永续会话有任务数、冲突数和开关对照；RSI 区分参与优化的任务与独立评测任务 | 引用结果时保留任务设置、模型、评价标准及比较条件；示例展示、优化内收益与独立验证分别表述，不把个案推广为任何任务都可靠 |
| 个人知识空间先采集整理再使用；Agent-Memory 区分离线建记忆和在线问答 | 写清计时和 token 的统计阶段及预处理成本；“在线更快”不能自动写成全流程更快或总成本更低 |
| Agent-Memory 原文将组件上线与 WorkSwarm 即将集成分别表述；Hyper-Agent 区分已有协作与未来资源协同构想 | 发布状态分别核实，不能把组件能力等同于应用已集成，也不能把规划图当成已实现部署 |
| 资产平台区分专家模板与运行实例，Hyper-Agent 区分 Agent 身份与不同会话状态 | 类比只辅助理解，保留对象、生命周期和边界；产品层概念与代码层实体要建立对应，不能因口语化合并成同一对象 |
| 样文含“首个”“做不到”“零改造”等宣传判断，个别标题层级、标点或年份有异常 | 学习其问题和论证结构；具体判断、兼容范围及论文信息另行核查。抓取格式和疑似笔误不作为规范，归档原文保留原样 |
| 归档含 `Accessed (UTC)` 和抓取元数据，历史正文可能使用“今天”“今年”“两个月前”等相对时间 | 抓取日期不当作发布日期；沿用历史时间关系前核对原始发布信息。不能把相对时间直接移到新稿，未确认的发布日期不补猜 |
| 归档正文保留视频标题和演示说明，但资料集没有视频文件 | 可据此学习脚本和观察点的写法；新稿需自己的有效素材或待制作占位，不能声称已观看原视频或借来已验证结论 |

## 模板中的运用

以下示例只解释写作安排，不能据此认定旧功能、实验或案例已被本次核实。按相应标题阅读，选定一种适合的推进方式即可，不必套齐所有示例。

### 标题与导语

永续会话标题以“长时工作如何不跑偏”提出任务问题，Computer Use 导语则把“操作电脑”拆成窗口、输入位置和结果确认等具体问题。先确定本篇已有依据的任务阻碍或发布变化，再生成标题和实际导语；可分别给“问题”“能力”“有依据的结果”角度的标题候选，不复制历史标题中的“首个”“首次”或情绪强度。任务问题不适合本篇时，可直接交代真实发布消息。

### 能力与任务

阅读 [Computer Use 的完整任务][cua-task]，看它怎样从邮件要求推进到会议安排和回复交付。概述可以写成：“以本篇材料中的一项任务为主线，先交代用户输入和验收要求，选出影响交付的关键操作，用结果核对说明任务怎样闭合，再提出下一章需要解释的机制问题。”正式填写时具体到本篇任务、关键转折与证据，不能仍保留“本篇一项任务”这样的空壳。能力本身不涉及跨应用时，不套用邮件和会议。

### 设计支撑能力

阅读 [RSI 的分层职责与工程闭环][rsi-design]，或[个人知识空间的整体流程][knowledge-design]。先选本篇一项能力要求，再沿真实职责、输入输出、状态变化或证据流解释设计为何起作用；最后指出条件、限制及可观察行为。多个设计点应分别补足能力，而不是把源码目录翻成章节。若借鉴 Agent-Memory 的分层说明，只学“不同信息承担不同用途”的解释方法，不能让新系统凭空多出相同层级。

### 接入与使用

阅读 [RSI 从准备到安装产物的路径][rsi-use]，并对照[永续会话的开启条件][persist-use]。选择本篇真实支持的一条路径，交代必要准备、有效入口、最少动作及可核对结果；对配置生效时机、权限等会影响首次使用的条件予以保留。样文中“无需改变习惯”之类概括不补足操作依据；只有源码接口时写集成路径，不虚构产品按钮。

### 差异与演示

阅读[永续会话的职责冲突 case][persist-case]：原文先交代谁有何种决定权，再选具体冲突，告诉读者在截图或视频说明中关注什么。或阅读 [Hyper-Agent 的逐步协作任务][hyper-demo]，观察同一任务如何扩展。把本篇每项关键点落成“任务条件与输入—关键操作或变化—本项视频／图片与观察点—能够支持的判断及边界”。需要对照时先核对比较条件，单方案演示只说明它展示的行为。

每项媒体在大纲中选定类型、编号、标题、位置和用途，文件命名及正文 PNG 要求按[媒体规范](../../media-workflow.md)执行，不照搬样文里的散列文件名。视频适合连续操作、状态切换和过程，图片适合关系、界面或结果对照；图片示意不能证明实际速度或成功率。素材待制作时写明计划及待验证问题；素材落地、替换及确认统一按[媒体确认边界](../../media-workflow.md#确认与归档边界)处理，演示不符时不倒改观察记录。样文原始资产不纳入本篇未引用图片清理。

### 收束与资源

阅读[资产平台的结语][assets-ending]，看它怎样从本篇资源关系回到后续复用。结语回扣已经论证的价值，再给符合本篇目的的一项或少量下一步。资源链接只保留本篇有关且核实过的入口，不复制原文全部仓库、合作背书或互动号召。

### 一份简短的借鉴记录

在大纲工作阶段采用时，可在模板“样文借鉴”内部字段写成：“Computer Use／01 日常任务，借鉴输入到交付的任务链；用于本篇能力章；任务、动作和产物改用资料 A 的记录。”填写真实样文位置、目标章节与改编内容即可，链接按目标文件位置重建；没有使用就移除此字段。事实和媒体来源分别记入既有事实／来源字段或媒体说明，不让一句借鉴记录代替核查。已确认后才新增的阅读或核查，按大纲变更规则判断，不为补记这句话改写历史大纲。

详细的借鉴说明在本文件维护，模板只链接相关示例。生成最终待确认稿时移除模板的参考区、提示和未选项；内部仅保留本篇实际采用的记录。它们随大纲确认和归档，不新增版本元数据字段或改变正文的大纲映射。
