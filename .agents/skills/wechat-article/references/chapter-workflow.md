# 正文逐章写作与确认

用于已确认大纲之后的成稿、完整改编或重写。大纲确认与变更见[大纲流程](outline-workflow.md)，落盘与版本编号见[版本规范](versioning.md)，图片／视频身份、文件命名和清理见[媒体规范](media-workflow.md)。本文件规定正文阶段的推进单位、资料核对、配图及章节确认。

## 顺序与范围

- 按已确认大纲依次处理：正文导语 → 各主章节 → 独立结语／资源章（若有）。按用户选择的粒度确认。主章模式把章导语、子章节和图放在一个单元；逐子节模式把主章 H2 和章导语放在首个单元，各实际子章节各有 H3 和稳定 ID，媒体挂到使用它的单元。用户选择章导语、子节逐个确认后续写沿用该模式。接续旧稿保留既有确认粒度，不用旧的主章批准补造子节确认。合并在末章的结语不另增单元。
- 大纲确认后，已有成稿请求的可开始第一个单元；只请求大纲时不自动写正文。即使大纲已包含接近成文的导语，仍要在正文阶段展示导语单元并取得确认，不能用大纲批准替代正文批准。
- 每次只完成并展示当前单元，未获确认不写下一单元。等待时可检查资料、代码和素材。用户已选在对话里确认时，在对话展示当前单元，延续已确定的顺序和粒度。
- 局部改稿只处理指定范围：核对、改写并确认受影响章节，不借此重写或重新确认其他未改章节。纯审稿、标题候选及尚未应用的修改建议仍保持原任务范围。

## 每章的循环

### 1. 写前核对

读取本章在所选大纲中的标题、概述、事实范围和媒体安排，并回看已确认前文的衔接。每章写前回查能支撑本章的可用来源，文档、原稿、实验记录或代码任一项均可；不强求资料与代码同时具备。提供了相关代码仓且本章涉及实现时，须核对本章入口、链路、配置和限制，可用代码理解技能定位后回查源码。代码是唯一来源时直接回查代码，不额外索要一份文档。

可以复用此前的来源定位与代码分析，但须针对本章重新查看关键依据、确认目标版本和相关变化，不以“整篇分析过”代替逐章核对。不重复做无关的全仓分析；无相关代码仓或本章不涉及实现时说明材料依据即可，不编造源码核查。

核心事实不足或与大纲冲突时，先补资料或按大纲变更流程处理，再写受影响内容；核查记录放在工作上下文或本篇 `refs/sources.md`，不回填已归档大纲。

### 2. 写作、润色与配图

按已定论证逻辑写本章，确认前完成[humanizer 润色及事实复核](facts-and-style.md#默认使用-humanizer-润色)，核对与大纲的一致性。

动笔前写清本单元给读者的新答案，并检查读者此时认识哪些术语和案例。相邻单元用一个未回答的问题或已说明的结果衔接。章节导语交代子节的关系和顺序，具体案例留给子节。解释扩展机制时，可以先讲从加载到生效的主链路，再分别写事件的触发时机、处理函数能调用的能力；完整接口清单可链接到开发文档。已经讲清的定义无需在每一节重述。

按本章已规划的图片逐项引导用户提供素材或生成图片：说明图片编号、标题、插入位置、要表达的关系／界面／结果及简短制作需求，提供“生成”或“添加已有图片”的合适路径。已有有效素材就直接核对并展示，不重复索要；需要生成时按下表选择适合的画图技能或工具，用户已授权生成的范围内直接执行，不重复请求同一许可。

#### 按图片类型选择生成方式

| 图片类型或需求 | 可选技能／工具 | 依据与交付重点 |
| --- | --- | --- |
| 技术架构、数据流、流程、时序、状态关系等结构图 | `fireworks-tech-graph` | 从已核实资料和代码提取节点、职责与连线，保留 SVG 等源文件并输出适合正文阅读的图片，不为视觉完整补造模块或调用关系 |
| 手绘风格、需要继续编辑的概念或协作关系图 | `excalidraw-diagram` | 适合用可编辑图形解释概念与关系，保留 Excalidraw 源文件；按需导出正文可使用的图片 |
| 封面、插画、场景视觉、概念示意或明确标注的界面构想 | `imagegen` | 按章节目的生成或编辑图像；概念图、构想图与真实界面截图明确区分，不能作为已实现功能或实测结果的证据 |
| 评测指标、性能趋势、成本或效果对比图 | 基于真实数据的绘图工具 | 核对数据、单位、基线及统计条件后绘制；不通过图像生成猜测数值、柱高或曲线 |
| 产品截图、操作结果和实验记录图 | 用户提供的真实素材或实际界面截取工具 | 核对版本和场景；生成的仿真界面不能冒充真实操作或实验记录 |

用户指定的画图技能、风格或可编辑格式优先；未指定时依据图片要表达的内容选择，不把所有配图交给同一种生成方式。只在实际绘制时读取当前环境中相应技能的 `SKILL.md` 并按其流程执行，不默认加载全部画图技能。技能不可用时说明情况，采用已有等效工具或引导添加素材，不声称调用了不存在的技能。

生成候选、采用转存、命名及真实 PNG 转换按[媒体规范](media-workflow.md)执行；仅聊天预览不自动建文章目录。

图片需要检查技术含义、文字、版本、图注与引用路径，并与本章文字一起展示供确认。没有规划图片且本章不需要时不强制增加。图片暂缺时保留明确占位；默认等用户补齐或生成，只有用户明确同意“本章确认、图片暂留占位”等安排，才可带着待补图项继续下一章。

本章计划使用视频时，按[媒体规范](media-workflow.md)采用用户指定的现有素材。素材待补时保留已确认的编号、标题、位置和状态，章节确认可以继续。设计中的案例按计划描述，实际采用后按画面更新文案。

### 3. 展示并等待确认

展示当前单元的完整正文及配图／获准占位，正文之外标明本章讨论稿标识（如“第二章第 2 轮”）、必要的核对说明和待补媒体，明确请用户确认本章。收到明确确认后才开始下一单元，不把沉默、工具预选或“再改一下”视为批准。

用户反馈后修改当前章，再次执行核对和润色，展示修改后的完整单元。精确的“把 X 改为 Y 后本章通过，继续下一章”可按大纲流程同等的附条件确认原则处理；若还需自主补写或解释，先展示修订稿再确认。用户一次明确批准当前单元的正文及配图安排时不重复追问。

记录实际确认的稿标识、用户回复、时间、对应文字和已采用媒体；具体快照格式见版本规范。确认文字不等于确认图片：回复范围不明确且影响是否可继续时，只澄清当前章的未决项；用户明确允许暂缺的图片和全部待补视频单列状态，不宣称素材齐备。

## 续写与已确认章节的修改

- 按[整体状态与稳定章节边界](state-contract.md#整体状态与恢复位置)接续本次首个需要写作／确认的单元，先核对工作稿、大纲和证据；不能因文件存在就当作批准。未改原文可合法继承，不因此重新确认；本次需要确认而缺少依据时才展示现稿取得确认，不倒填旧记录。
- 已确认章节的正文或图注含义发生改变，先核查其他章节影响，再展示受影响章节的新稿重新确认；其余不受影响章节保留原确认。媒体变化统一按[确认与归档边界](media-workflow.md#确认与归档边界)处理：呈现信息未变的格式转换不重复确认，占位落地核对实际素材，内容改变检查全部使用章节，不能把占位批准当作素材实物批准。
- 变化触及标题、关键事实、主线、章节逻辑或媒体计划时，先修订并确认大纲，按[版本规则](versioning.md#统一命名)保存，再更新受影响章节。切换大纲基线后逐章检查适用性，未变且仍符合新大纲的章节可保留原确认及其原始上下文，在 `outline_revalidation` 记录核对结论，不伪造针对新大纲的批准，也不新增逐章审批。
- 用户要求返工前章时，先暂停下一章，完成前章及必要关联章节的修改与确认后再续写。不能因为章节已确认而保留已发现的事实错误。
- 指定一段或一句时，使用稳定 ID 和准确原文定位；只替换目标，核对其他单元的内容和确认记录。落盘时可用 `edit-section`，先保存目标原稿快照。「回到上一版」从该单元的实际快照恢复；确切旧稿或确认记录不可获得时先说明缺口，不凭记忆替换。已确切确认且未受影响的后续单元继续有效。
- 对用户要求直接改的精确指令，或按段确认后要批量同步正文、大纲及配图时，使用[局部改稿计划](revision-workflow.md)。保持后续已写但尚待确认的原文和状态。

## 全部章节确认之后

大纲或正文有视频计划时，按 `VID` 编号汇总标题、规范文件名、使用章节和插入位置，列出仍待提供的文件或链接。演示视频附上对应案例、脚本和观察点。已有视频直接核对命名、内容与采用依据，可集中核对涉及的素材和章节。用户同意延期时记录保留的占位。

按已确认顺序汇总全文，核对过渡、指代、媒体对应、事实和版本映射。汇总阶段只做检查、拼接及已批准的媒体落实，不再次全篇改写已确认文字；确需改措辞或逻辑时，返回受影响章节确认，涉及大纲则先处理大纲。无需另设例行的全文审批。

各单元确认有效、媒体已落实或获准保留占位且检查通过后，按版本规范归档，交付列出待补项。用户明确要求清理时，按[媒体清理](media-workflow.md#正式完稿后的统一删除)执行。
