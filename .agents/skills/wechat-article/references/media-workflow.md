# 图片、视频与临时素材管理

本文件统一媒体身份、格式、确认边界和清理。[章节流程](chapter-workflow.md)决定何时处理配图、视频，[版本规范](versioning.md)管理正文映射。仅审稿、建议或聊天预览不自动建目录或清理；单独生成／保存图片按用户指定资产范围执行。

## 编号、标题与文件名

- 图片、视频分别使用 `IMG-01`、`VID-01` 等至少两位内部 ID，初稿按首次出现顺序分配；确认后新增从同类历史最大 ID 继续，插入和删项不重排、不复用内部 ID。跨章复用同一素材沿用 ID，关联全部使用章节。读者编号按场景及本篇约定，可在工作稿中按首次出现顺序重排。
- 大纲、正文和媒体记录使用同一个内部 ID 映射同一素材。大纲标题服务于媒体计划，正文显示标题服务于读者，规范文件名按素材登记名生成。调整读者标题时更新正文和 `caption.title`；需要同步大纲或改文件名时按用户指定范围和实际引用处理。
- 新稿使用「图1」「视频1」等读者编号，`caption` 记录显示编号、标题和描述。先读取[场景和本篇媒体偏好](revision-workflow.md#本篇偏好与格式审阅)再排版；未配置的场景默认图注在图下、视频标题链接与描述分段。重排读者编号时同步引用、图注、文件名和大纲，内部 ID 保持稳定。详细演示目标、脚本和验收点留在内部计划。
- 文件名默认用 `<编号>_<标题>_vNNN.<实际扩展名>`，如 `IMG-01_整体架构_v001.png`、`VID-01_任务演示_v001.mp4`。媒体修订号从 `v001` 起，至少三位、按数值递增，独立于大纲／正文版本。未归档的视频仅调整标题或文件名且字节相同时，直接重命名，沿用原修订号并更新本轮引用。其他内容、标题或已交付字节变化时，从历史记录及文件（含暂存）的最大修订号加一，保留旧文件。为尚未交付的同一选定源图首次导出 PNG 不必另增修订。
- 对应 PNG／SVG 同主名、同修订；其他必要编辑源文件及依赖按实际登记。在线视频也核对实际规范文件名，无法核对就列待核对，不把约定名称冒充已有文件。
- 用户指定修改 `assets/images/` 的文件名时，重命名工作区的 PNG 和配套 SVG，同步正文路径、媒体登记和实际引用这些文件的大纲链接。用户要求文件名只含图号和图名时，使用 `图N_图名.png` 和同名 SVG，修订号仍记在素材记录里。导出包沿用正文的实际引用路径。

正文推荐写法（修订号不必显示在读者标题中）：

```markdown
![IMG-01 整体架构](assets/images/IMG-01_整体架构_v001.png)

图 IMG-01：整体架构

[视频 VID-01：任务演示](assets/videos/VID-01_任务演示_v001.mp4)
```

未提供实物时用 `【图片占位 IMG-01：整体架构；待绘制】`、`【视频占位 VID-01：任务演示；待提供】` 等文本，不创建虚假文件引用。场景要求逐项演示时，每项关键竞争力／差异仍须自己的具体 case 和独立媒体，不能靠复用同一泛化媒体替代。

## 正文图片统一使用 PNG

- 正文实际引用本地可读的真实 `.png`，图注和 alt 均包含对应编号及标题。其他格式须真实转换或导出，检查中文、标注、清晰度、透明度、裁切和技术信息；不只改扩展名，也不增删技术信息或数据。
- 新稿在本版 `assets/images/` 保存图片及必要源文件，在 `assets/videos/` 保存本地视频。正文里的链接相对于版本目录。含空格等字符使用有效 Markdown 路径。未进入正文的封面／发布图可保留适用格式。
- 参考资料和历史样文保持原归档；复用图片时在本篇建立规范副本。旧正式正文不重写，需修改时通过新版本采用现行规范，格式迁移不扩大局部改稿范围。

## 与章节和版本记录衔接

大纲规划编号、标题、所属章节、位置、用途和形式；配图随章核对、视频统一处理的节奏按章节流程执行。媒体状态、字段及证据格式统一见[状态契约](state-contract.md#唯一数据契约)。

- 媒体按唯一 ID 登记，复用关联全部 `section_ids`。`body` 是正文媒体；已实际采用的 `cover`／`publishing` 虽未嵌入正文也须保留，候选不能靠改角色逃过整理。不强制每篇制作封面。
- 生成候选副本收集到本篇 `.tmp/candidates/`，登记路径、散列和来源。采用后按类型转存到本版素材子目录。工具全局原件不自动删除。
- 本地媒体记录实际文件散列；仅在线视频可保存已核对 URL、规范文件名及核对时间，无需下载或虚构散列。纯计划用占位，到位未采用不能当作批准。用户指定采用并说明内容时可在当前节落实。内容仅来自用户说明时，注明依据及核对范围。
- `source_files` 只登记实际保留的源图和必要依赖及散列；原始资料来源另记，不把所有下载原图和导出候选都当作依赖。多章复用时，内容变化回查全部使用章节。
- 正文归档保存本版媒体及源文件快照。跨版本复制同一实物时保留媒体编号和修订号，并登记新路径。已确认内容中的媒体文件换成字节相同的本版副本时，按媒体更新链记录路径变化。媒体修订、章节讨论轮次和文章版本独立编号。

### 确认与归档边界

| 变化 | 处理 |
| --- | --- |
| 仅规范文件名、修路径或导出 PNG，编号、标题、呈现信息、图注及用途不变 | 核对结果和散列，记录 `media_updates`，不重确认大纲／章节；缺字、裁切等信息变化先修复 |
| 只修改读者标题、精简说明或移除重复说明，媒体事实与用途不变 | 用 `edit-caption` 更新正文和显示字段，保留编号、文件与既有确认，登记用户指令；按需要更新当前版中的引用 |
| 原计划的占位落成实物，或同计划更换素材 | 用户明确指定文件及目标时直接采用，记录采用依据。论述及图注意义未变时核对素材、引用和散列，沿用章节确认。占位批准不代替实物批准 |
| 媒体事实、图注意义或论证改变 | 核查并确认受影响章节；触及大纲主张、标题或媒体计划时先确认新大纲 |
| 已正式交付的正文需要补图、换图或修改引用／文字 | 按[版本规则](versioning.md#统一命名)取得新增版本的授权后再开工作态，保留已交付的历史文件及快照 |

免重确认变化的精确替换和依据按[媒体更新链](state-contract.md#媒体更新链)记录，不能借媒体操作修改普通论述。阶段归档后，用户仅补充“最终交付保留既有占位”的依据，可更新当前待办处置而不改历史快照；实际交付媒体发生变化则开启新工作态。

### 采用用户指定的本地媒体

对已登记的正文视频或 PNG 图片，用显示编号预览采用或替换。加 `--apply` 提交文件、正文及素材记录。

```powershell
python -B -X utf8 .agents/skills/wechat-article/scripts/article_workflow.py adopt-media '<软文目录>' --media-number '视频6' --source '<本地视频.mp4>' --basis '<用户采用指令>' --apply
```

采用 PNG 时可用 `--svg '<本地源图.svg>'` 同时登记配套的自包含 SVG。PNG 与 SVG 共用文件主名和修订号，正文引用 PNG。配套 SVG 改变时，即使 PNG 字节相同也采用新素材修订。

1. 用读者编号定位 `caption.number`，结合媒体类型、所在章节和现有链接确认内部 ID。首次补占位用首个可用修订号，已有视频换成不同文件时用下一修订号。
2. 将文件放入当前版 `assets/videos/`，核对文件与登记散列，并同步正文链接、媒体记录和大纲中现有的实际链接。补占位时一并解除该视频的待补状态。
3. 只替换文件时核对路径、扩展名和散列。用户说「不用看视频」时按素材指令直接执行，记录用户指定的文件和实际做过的核对。需要按画面修改说明时再按实际画面取证。用户给了新版功能说明时，正文案例、视频说明和大纲里的对应说明按本轮授权同步，删去旧材料中失去依据的功能描述。
4. 用户明确要求删除旧版时加 `--delete-previous`，要求删除 `--source` 指定的原始文件时加 `--delete-source`。两个参数可独立使用，预览会列出拟删除路径。应用时先校验采用副本与正文引用，再检查其他工作稿、归档正文、大纲和素材登记。仍被引用或仍是当前采用文件时停止删除，并报告具体路径。仅提供替换指令时保留源文件和旧版。

## 版本确认后的未引用图片暂存

例行整理在正文正式归档后执行。用户已明确要求清理未引用图片时，按其指定范围核对保留集合后执行，已引用 PNG 的同名 SVG 和登记依赖一并保护。

1. 读取本篇全部保留正文、已确认大纲及当前有效工作稿的实际引用（含 Markdown 和 HTML），加入已采用封面／发布图，建立保留集合。无法解析、文件缺失或源图关系不明时先解决；只查最新稿不足以判断废图。大纲纯媒体规划文字不保护所有同主题候选。
2. 被引用图片及已登记的对应 SVG、必要源文件与依赖一起保留，旧 JPG／SVG 引用同样受保护；不重写历史文件来腾空间。
3. 将本版 `assets/` 和旧布局共享 `article/assets/` 内未保留的图片移到 `.tmp/images/<批次>/`。生成候选留在 `.tmp/candidates/`，目标冲突时换批次。视频、非图像编辑文件及其他版本目录不在扫描范围。
4. 移动后复核引用仍可读取。后续采用暂存图先恢复到目标版本的 `assets/images/`，核对命名和引用再进入章节流程，正文不能直接引用 `.tmp`。

所有移动／恢复／删除都验证解析后路径在本篇允许范围内且不跟随目录链接。计划与实际结果追加至 `metadata.json.asset_maintenance`，记录操作／批次、正文版本、时间、路径、散列、原因及 `planned/completed/failed` 状态，不放在将删除的 `.tmp` 中。中断按状态工具恢复，操作日志不推进文章版本。

## 正式完稿后的统一删除

正式完稿须满足：本次最终成稿任务已完成或用户明确表示完稿，章节确认有效，媒体到位或获准在最终交付保留占位，全文复核通过且最终正文已归档。按契约记录 `finalized` 及完成依据；仅阶段稿、返工中或仍有未决选择时不作完稿，重开改稿清空完稿标记。这是记录已有结论，不新增全文审批。

大纲审阅页面、同名 JSON、反馈回执和手机预览写到本篇 `.tmp` 时自动登记。手动生成图片候选或采集临时文件后，用 `register-temp` 记录来源、版本、路径和散列。可重复传入 `--temp-file` 登记同一来源的一组文件。

```powershell
python -B -X utf8 .agents/skills/wechat-article/scripts/article_workflow.py register-temp '<软文目录>' --temp-file '<.tmp 下的生成文件>' --origin '<生成工具或流程>' --version v001 --apply
```

用户明确要求清理时，用 `finalize --cleanup --apply` 在正式 ZIP 校验后清理工作稿和已登记的未引用临时产物；仅清理已登记临时素材时可单独使用 `clean-temp --apply`。文件的目录和扩展名不能单独证明归属。未登记、仍被引用、属于更新版本或散列与登记不符的文件继续保留。命令和恢复方式见[工具使用](state-contract.md#工具使用)。
