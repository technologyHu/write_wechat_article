# 图片、视频与临时素材管理

本文件统一媒体身份、格式、确认边界和清理。[章节流程](chapter-workflow.md)决定何时处理配图、视频，[版本规范](versioning.md)管理正文映射。仅审稿、建议或聊天预览不自动建目录或清理；单独生成／保存图片按用户指定资产范围执行。

## 编号、标题与文件名

- 图片、视频分别使用 `IMG-01`、`VID-01` 等至少两位编号，初稿按首次出现顺序分配；确认后新增从同类历史最大编号继续，插入和删项不重排、不复用旧号。跨章复用同一素材沿用 ID，关联全部使用章节。
- 编号和标题在大纲、正文图注／视频标题及媒体记录中一致。标题简明概括内容，避免 Windows 非法文件名字符、控制字符和末尾空格／句点；需调整时同步大纲及受影响内容。
- 文件名为 `<编号>_<标题>_vNNN.<实际扩展名>`，如 `IMG-01_整体架构_v001.png`、`VID-01_任务演示_v001.mp4`。媒体修订号从 `v001` 起，至少三位、按数值递增，独立于大纲／正文版本；内容、标题或已交付字节变化时从历史记录及文件（含暂存）的最大修订号加一，不覆盖旧文件。为尚未交付的同一选定源图首次导出 PNG 不必另增修订。
- 对应 PNG／SVG 同主名、同修订；其他必要编辑源文件及依赖按实际登记。在线视频也核对实际规范文件名，无法核对就列待核对，不把约定名称冒充已有文件。

正文推荐写法（修订号不必显示在读者标题中）：

```markdown
![IMG-01 整体架构](assets/IMG-01_整体架构_v001.png)

图 IMG-01：整体架构

[视频 VID-01：任务演示](assets/VID-01_任务演示_v001.mp4)
```

未提供实物时用 `【图片占位 IMG-01：整体架构；待绘制】`、`【视频占位 VID-01：任务演示；待提供】` 等文本，不创建虚假文件引用。场景要求逐项演示时，每项关键竞争力／差异仍须自己的具体 case 和独立媒体，不能靠复用同一泛化媒体替代。

## 正文图片统一使用 PNG

- 正文实际引用本地可读的真实 `.png`，图注和 alt 均包含对应编号及标题。其他格式须真实转换或导出，检查中文、标注、清晰度、透明度、裁切和技术信息；不只改扩展名，也不增删技术信息或数据。
- 采用素材放在本篇 `article/assets/`，正文路径相对于 `article/`；含空格等字符使用有效 Markdown 路径。未进入正文的封面／发布图不强制转换为 PNG；一旦用于正文仍遵守正文格式。
- 参考资料和历史样文保持原归档；复用图片时在本篇建立规范副本。旧正式正文不重写，需修改时通过新版本采用现行规范，格式迁移不扩大局部改稿范围。

## 与章节和版本记录衔接

大纲规划编号、标题、所属章节、位置、用途和形式；配图随章核对、视频统一处理的节奏按章节流程执行。媒体状态、字段及证据格式统一见[状态契约](state-contract.md#唯一数据契约)。

- 媒体按唯一 ID 登记，复用关联全部 `section_ids`。`body` 是正文媒体；已实际采用的 `cover`／`publishing` 虽未嵌入正文也须保留，候选不能靠改角色逃过整理。不强制每篇制作封面。
- 生成候选副本收集到本篇 `.tmp/candidates/`，登记路径、散列和来源；采用后转存 `article/assets/`。工具全局原件不自动删除。
- 本地媒体记录实际文件散列；仅在线视频可保存已核对 URL、规范文件名及核对时间，无需下载或虚构散列。纯计划用占位，到位未采用不能当作批准。
- `source_files` 只登记实际保留的源图和必要依赖及散列；原始资料来源另记，不把所有下载原图和导出候选都当作依赖。多章复用时，内容变化回查全部使用章节。
- 正文归档保存本版媒体及源文件快照。媒体修订、章节讨论轮次和文章版本独立，不因其中一个变化自动推进其他编号。

### 确认与归档边界

| 变化 | 处理 |
| --- | --- |
| 仅规范文件名、修路径或导出 PNG，编号、标题、呈现信息、图注及用途不变 | 核对结果和散列，记录 `media_updates`，不重确认大纲／章节；缺字、裁切等信息变化先修复 |
| 原计划的占位落成实物，或同计划更换素材 | 展示实际素材并记录采用依据；用户已明确提供并指定采用时不再询问。论述及图注意义未变，只核对媒体，不重审整章；占位批准不代替实物批准 |
| 媒体事实、图注意义或论证改变 | 核查并确认受影响章节；触及大纲主张、标题或媒体计划时先确认新大纲 |
| 已归档正文补图、换图或修改引用／文字 | 先在工作态按上述规则处理，再保存新正文版本，保留历史文件及快照 |

免重确认变化的精确替换和依据按[媒体更新链](state-contract.md#媒体更新链)记录，不能借媒体操作修改普通论述。阶段归档后，用户仅补充“最终交付保留既有占位”的依据，可更新当前待办处置而不改历史快照；实际交付媒体发生变化则开启新工作态。

## 版本确认后的未引用图片暂存

本轮所需确认及检查完成、正文已正式归档后才整理，不在单章刚确认时提前清理。

1. 读取本篇全部保留正文、已确认大纲及当前有效工作稿的实际引用（含 Markdown 和 HTML），加入已采用封面／发布图，建立保留集合。无法解析、文件缺失或源图关系不明时先解决；只查最新稿不足以判断废图。大纲纯媒体规划文字不保护所有同主题候选。
2. 被引用图片及已登记的对应 SVG、必要源文件与依赖一起保留，旧 JPG／SVG 引用同样受保护；不重写历史文件来腾空间。
3. 仅将本篇 `article/assets/` 内未保留的图片移动到 `.tmp/images/<批次>/`，生成候选留在 `.tmp/candidates/`。目标冲突换批次，不覆盖。视频、非图像编辑文件不在自动图片扫描内；参考资料、样文、外部文件和其他软文均不移动。
4. 移动后复核引用仍可读取。后续采用暂存图先恢复至 `article/assets/`、核对命名和引用再进入章节流程，正文不能直接引用 `.tmp`。

所有移动／恢复／删除都验证解析后路径在本篇允许范围内且不跟随目录链接。计划与实际结果追加至 `metadata.json.asset_maintenance`，记录操作／批次、正文版本、时间、路径、散列、原因及 `planned/completed/failed` 状态，不放在将删除的 `.tmp` 中。中断按状态工具恢复，操作日志不推进文章版本。

## 正式完稿后的统一删除

正式完稿须满足：本次最终成稿任务已完成或用户明确表示完稿，章节确认有效，媒体到位或获准在最终交付保留占位，全文复核通过且最终正文已归档。按契约记录 `finalized` 及完成依据；仅阶段稿、返工中或仍有未决选择时不作完稿，重开改稿清空完稿标记。这是记录已有结论，不新增全文审批。

完稿后执行 `clean-temp --apply` 删除本篇已登记临时素材并追加实际结果，无需例行清理审批。工具检查阶段、路径／链接、保留依赖、归属和散列；未知或已变动的临时文件阻止整批删除，先查明，不为通过检查而改日志。失败保留可核对状态，如实报告已暂存／已删除的范围。命令和恢复方式见[工具使用](state-contract.md#工具使用)。
