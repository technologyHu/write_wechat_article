# 微信公众号文章写作

先识别用户要交付什么，以及结果留在对话中还是写入文件。接续已有稿件时，核对目标稿件、版本、当前单元、确认记录和审阅渠道，再从该处继续。登录公众号、上传素材和对外发布需要另行明确请求。

## 选择写作场景

- `openjiuwen` 适用于明确为 openJiuwen 公众号写作，或以 openJiuwen／WorkSwarm 的能力为传播主体的稿件。选中后读取[场景约定](references/scenarios/openjiuwen.md)，按需使用该场景的模板、样文和媒体要求。
- 没有明确适用的专用场景时，使用 `general`。按本篇受众、目的和证据组织内容，媒体按需安排。参考材料中出现品牌名时，仍按本篇传播主体和用途判断。
- 接续稿件沿用已确认的场景。用户明确调整用途或场景时，按本次要求重新判断。

## 从当前任务开始

| 用户要做什么 | 交付范围与入口 |
| --- | --- |
| 准备素材或做选题 | 给出有依据的主张、案例、证据位置和待核实项。选题补充读者问题和写作角度。要求保存时按[资料归档](references/versioning.md#参考材料与历史追溯)处理。 [素材准备](references/facts-and-style.md#技术素材准备) |
| 拟标题、摘要或单独导语 | 按要求给候选或成稿，保持事实主线和指定篇幅。 [事实与表达](references/facts-and-style.md) |
| 拟大纲或调整大纲 | 按顺序确认各级标题，再逐项核对导语、各节概述和媒体安排，最后确认完整大纲。优先使用 HTML 向导并复用同一页面，按用户选择的渠道核验反馈。 [大纲流程](references/outline-workflow.md) · [HTML 向导](references/outline-review-ui.md) |
| 写新稿、完整改编或重写 | 使用已确认的大纲。需要新大纲时先走大纲流程。按已定粒度核查、写作和处理计划中的配图，当前单元确认后再写下一单元，最后汇总。 [逐章流程](references/chapter-workflow.md) |
| 局部改稿或润色 | 按用户要求给建议、预览或直接应用明确指定的修改。同步受影响的正文、大纲和媒体引用，保留其他已确认内容。 [局部改稿](references/revision-workflow.md) |
| 审稿、事实核查或格式审阅 | 指出问题、依据及所在位置。用户要求应用修订时再进入改稿流程。 [事实与表达](references/facts-and-style.md) · [格式审阅](references/revision-workflow.md#本篇偏好与格式审阅) |
| 管理媒体、归档或导出 | 核对媒体身份、引用和保留范围，按指定版本处理。导出 ZIP 包含该版正文及引用资产，同版重导覆盖原 ZIP。清理按用户指定范围执行。 [媒体规范](references/media-workflow.md) · [版本导出](references/versioning.md#导出指定版本) |

可以组合多个任务，按用户要求的交付边界推进。仅请求素材、选题、标题、建议或审稿时，到对应结果为止。仅在对话中交付时，保留对应的写作与确认流程，无需创建版本目录或运行状态工具。

预览、已回传和已确认分别记录。用户改用对话审阅时，沿用当前轮次和已有确认，从该渠道继续。只有实际收到的用户回复才能作为确认依据。 [反馈与回传](references/outline-review-ui.md#渲染和回传)

## 使用本篇资料

- 复用对话和稿件中已有的主题、读者、目的、范围和来源。只询问当前步骤缺少的信息。局部润色以原稿和用户指定范围为输入，保持术语、论证和适用条件。
- 写作中的事实主张需要相关且可读取的依据，例如原稿、采访、公开资料、实验记录或源码。依据不足时，先完成可交付的选题、结构或有证据的部分，并指出需要补充的具体事实。样文可用于借鉴写法。
- 涉及具体实现时，以用户指定的代码仓和目标版本为准，按本篇范围回查。源码会影响结论且尚未指定时，可以询问一次并允许跳过。仅保存网页用 `web-article-fetcher`，只需取证时按所需内容读取。 [事实核查与润色](references/facts-and-style.md)
- 新写或重写面向读者的文字时，按事实与表达规范使用 `humanizer`，复核改写后的事实和限定条件。精确替换及排版操作按用户指定内容执行。 [润色规范](references/facts-and-style.md#默认使用-humanizer-润色)

## 文件交付与检查

- 落盘时优先采用指定目录或现有布局。通过元数据核对大纲、正文和版本的绑定关系。按任务选用检查、预览、恢复或写入命令。 [目录与版本](references/versioning.md) · [状态契约和工具](references/state-contract.md)
- 交付前核对本次涉及的事实与来源、标题层级、媒体命名和相对链接。正文用一个 H1 标题，主章节用 H2，子章节用 H3。内部依据与确认状态放在正文之外。汇总时保留已确认的文字，实质修订回到受影响单元处理。
- 报告实际交付的文件、版本对应关系和待补项。区分工作稿、已确认稿和实际生成的 ZIP。
